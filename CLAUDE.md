## Project Overview

This is a GraphQL API server for OSWatcher that uses Neo4j as the database and provides filesystem analysis, diff computation, and search capabilities. The server includes:
- GraphQL API with WebSocket subscriptions
- REST API for blob downloads
- S3/MinIO integration for blob storage
- Windows registry value filtering for sensitive data (disabled by default -- see below)

**Open-source release note:** sensitive registry value redaction is commented
out by default (not deleted) in `src/index.ts`, so a self-hosted instance has
full functionality with no configuration required. See
`docs/reference/access-restrictions.md` for what it does and how to re-enable
it. Blob download authorization (branch-based blocking of Windows binaries) was
removed entirely on 2026-09-08; it is in git history.

## Architecture

### Core Technologies
- **Apollo Server 4** with Express 5 middleware for GraphQL API
- **Neo4j GraphQL Library** for schema-first GraphQL development with `@neo4j/graphql` directives
- **Neo4j Driver** for direct database queries and transactions
- **TypeScript** with ES2022 target and NodeNext modules (ESM)
- **WebSocket** support via `graphql-ws` for GraphQL subscriptions
- **AWS S3 SDK** for MinIO object storage access
- **Zod** for runtime validation

### Server Architecture

#### Entry Point (`src/index.ts`)
The main server file that orchestrates all components:
- Validates environment variables with `envalid`
- Initializes Neo4j driver and applies constraints via `src/constraints.ts`
- Creates dual HTTP/WebSocket server on port 4000
- Sets up three endpoints:
  - `/graphql` - GraphQL API with WebSocket subscriptions
  - `/blob/:hash` - REST API for blob downloads
- Implements security features:
  - Rate limiting (100 requests/minute, 5 WebSocket connections per IP)
  - Query complexity validation (max 100 fields)
  - Sensitive error message filtering
  - Response filtering for sensitive registry values

#### GraphQL Layer

**Schema (`type-defs.graphql`)**
- Defines filesystem entities: Blob, Tree, Commit, Branch
- Windows-specific types: WinRegKey, WinRegValue, Symbol, Struct, StructField, DataType
- Custom query types for diff operations, commit history, search, and path traversal
- Uses `@neo4j/graphql` directives: `@query`, `@mutation`, `@limit`, `@relationship`, `@unique`
- Default and max limits set to 5000 for most types

**Resolvers (`src/resolvers.ts`)**
Custom resolvers for operations not auto-generated by Neo4j GraphQL:
- `diffNodesAt` - Computes diff between two commits at a specific path
- `fetchCommitHistory` - Retrieves commit history with pagination
- `search` - Searches filesystem paths across commits
- `traversePath` - Navigates filesystem tree structure

#### Blob Storage

**REST Routes (`src/rest-routes.ts`)**
- Express router for blob downloads at `/blob/:hash`
- Uses S3 SDK to fetch blobs from MinIO with authenticated requests
- No per-blob access control: every stored blob is downloadable by hash
- Winbindex fast path (`src/winbindex.ts`): when `?filename=` names a Windows PE
  file (`.exe`/`.dll`/`.sys`), the blob is resolved on Winbindex, downloaded from
  Microsoft's symbol server and SHA-1-verified before a single byte is sent;
  every miss or failure (including a hash mismatch) falls back to MinIO unchanged. See `docs/reference/winbindex-source.md`.

#### Data Processing

**Diff System (`src/diff/`)**
- `diff.ts` - Iterative tree diffing with async generators for memory efficiency
- `utils.ts` - Type conversion utilities between Neo4j and GraphQL types
- `types.ts` - TypeScript type definitions for diff results
- Computes NEW, MOD, DEL status for filesystem changes
- Uses custom Cypher queries for efficient Neo4j graph traversal

**Search (`src/search.ts`)**
- Implements filesystem path search with full path reconstruction
- Returns results with commit context
- Supports different commit scopes: SINGLE, HISTORY, HISTORY_WITH_UPDATES, RANGE

**Registry Filtering (`src/registry-response-filter.ts` & `src/registry-filter-config.ts`)**
- Recursively filters sensitive Windows registry values from GraphQL responses
- Handles connection-style and diff-style response patterns
- Redacts values like DigitalProductId, ProductId (configurable via `SENSITIVE_REGISTRY_VALUES`)
- Applied via Apollo Server plugin in `willSendResponse` hook

### Database Integration
- Neo4j constraints are applied on startup via `src/constraints.ts`
- Uses both OGM (Object Graph Mapping) and direct Cypher queries
- Session-per-transaction pattern with `executeRead`/`executeWrite` for safe concurrent operations
- Custom Cypher queries defined in `src/queries.ts`

### Configuration
See README.md for complete `.env` setup. Key variables:
- **Neo4j**: `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`
- **Storage**: `OBJECT_STORAGE_URI`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_OBJECTS_BUCKET_NAME`
- **Optional**: `NODE_ENV`, `SENSITIVE_REGISTRY_VALUES`
- **Winbindex fast path** (optional, all defaulted): `WINBINDEX_ENABLED`, `WINBINDEX_DATA_URL`, `WINBINDEX_SYMBOL_SERVER_URL`, `WINBINDEX_FETCH_TIMEOUT_MS` — see `docs/reference/winbindex-source.md`

## MCP Server (`mcp/`)

The MCP (Model Context Protocol) server exposes OSWatcher tools to AI assistants. It is a **separate Docker service** — not part of the `api` container.

- **Location**: `graphql-api/mcp/`, with its own `Dockerfile`, `package.json`, `tsconfig.json` and codegen. The root `tsconfig.json` excludes it.
- **Compose service**: defined in `oswatcher-hub/compose.dev.yml` as `mcp`, port 3001, built from `context: ../graphql-api`. The two repos must be siblings on disk.
- **Rebuilding**: must be rebuilt explicitly — `docker compose -f compose.yml -f compose.dev.yml up --build mcp -d`. Rebuilding `api` does NOT rebuild `mcp`.
- **GraphQL client**: calls the API at `GRAPHQL_API_URL` (`http://api:4000/graphql` in Docker). The API is unauthenticated, so no credential is forwarded and the SDK is built once at module scope.
- **Codegen**: `npm run generate` (not `codegen`) regenerates `src/graphql/generated/sdk.ts` from `src/graphql/queries.graphql`. It reads the schema from a **running** API on port 4000.

### Key design constraints

**Filesystem diff filter**: `DiffNodesAt` **must** pass `filter: ["Tree", "Blob"]` when diffing filesystems. Without it, the Java procedure (`example.diffTreesRecursive`) defaults to filtering only `Tree` nodes and silently drops every `Blob` leaf. See `docs/explanation/diff-system.md`.

**`max_depth=1` required for Symbol, Struct and StructField diffs**: the Java procedure adds `parentLabel` to the filter and recurses into Struct/Symbol nodes, but their children are `StructField`, not `Struct`/`Symbol`. Without `max_depth=1` the diff silently returns 0 results.

**UNCHANGED status filter for a full C type layout**: to reconstruct a whole struct (e.g. `_EPROCESS`, 261 fields) pass `status_filter: ["NEW", "MOD", "DEL", "UNCHANGED"]`. Without it only the delta comes back (~5 items).

**Search sessions are process-local**: `src/search-session.ts` holds them in a `Map`, so the API cannot be horizontally scaled while sessions are in use.

## Important Patterns

### Module System
- Project uses ESM (`"type": "module"` in package.json)
- All imports must use `.js` extensions, even for `.ts` files (TypeScript ESM requirement)
- Example: `import { foo } from "./bar.js"` when importing from `bar.ts`

### Neo4j Patterns
- Session-per-transaction: always create new session for each operation
- Use `executeRead` for read operations, `executeWrite` for write operations
- Always close sessions in `finally` blocks
- Custom Cypher queries coexist with OGM-generated operations

### Security Patterns
- No per-user authentication. Auth0 was removed when the project went fully
  open source; the access restrictions it guarded are disabled or removed.
- Sensitive data filtering (registry redaction) happens at response time, not
  query time, and fails open on error

### GraphQL Patterns
- Schema-first development with `type-defs.graphql`
- Custom resolvers for complex operations; auto-generated for simple CRUD
- Type generation via `npm run gentypes` (creates `src/ogm-types.ts`)
- Async generators for streaming large result sets (diff operations)
